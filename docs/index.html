01 / The engineering

Useful autonomy.
Explicit boundaries.

A model calling a tool is the easy part. This project makes the surrounding system inspectable: who can submit a task, what can execute, which evidence supports the answer, and how the run ends.

01

A finish line for every run.

A Python controller enforces a 3–8 step budget, bounded model output and a runtime deadline. Success, insufficient evidence, invalid tools and step limits have distinct outcomes.

02

Two tools. Clear contracts.

A restricted arithmetic parser and curated knowledge search. Pydantic validates arguments before execution; final citation IDs must come from the observations actually retrieved.

03

A trace you can inspect.

The interface shows ordered actions, observations, sources and termination reasons. It never displays private model reasoning. The static demo lets you explore that experience immediately.

04

Cloud execution with ownership.

Cognito protects API access. JWT-derived ownership isolates runs. SQS decouples submission from the worker, and conditional DynamoDB claims skip already claimed messages.

01 — Submit & authenticate

Cognito SRP sign-in → access JWT → HTTP API authorizer. FastAPI records a QUEUED run, sends its ID to SQS, and returns HTTP 202.

02 — Execute & record

A separate worker claims the run, calls Bedrock Converse, validates actions, executes tools, and stores ordered step events in DynamoDB.

03 — Poll & finish

The UI polls metadata and events every two seconds and stops at a terminal state. Every read checks ownership. Logs and alarms support diagnosis.
